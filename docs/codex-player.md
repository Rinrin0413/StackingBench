# Codex セッションとの対戦

`codex` プレイヤーは、現在の Codex セッションが専用コマンドを通じて手を選ぶ接続口です。StackingBench はモデルを起動せず、OpenAI API や追加の API キーも使いません。既存の会話文脈とツール利用があるため、API 接続の `llm` / `llm-preview` とは別の条件として保存します。Codex 自体の使用量・利用条件はこのアプリから取得しません。

## 画面で準備する

1. 自分を「人間（あなた）」、相手を「Codex · このセッション」に設定します。
2. Codex 欄のモデル名と推論レベルを実際のセッション設定に合わせます。今回の画面初期値は、ユーザー指定の `GPT-6 Astra` / `High` です。これは記録用で、Codex のモデル設定そのものを変更しません。必要に応じて「観測・生成・探索の設定」の Codex 試し読みを切り替えます。既定はあり、1判断32遷移です。生成トークン・思考設定・API要求間隔は Codex セッションには適用しません。
3. 対局を作成すると、自分の番なら操作でき、Codex の番なら入力待ちになります。
4. 実際に対戦する時、この会話で「Codex と対戦開始」と伝えます。画面の「対戦依頼をコピー」には対局IDも含まれます。

ブラウザ操作だけでは Codex セッションを起動・通知しません。Codex がこの会話で動作中に専用コマンドで盤面取得・手の確定・次の番の待機を行います。会話の処理が終了・中断した場合、盤面はそのまま入力待ちです。「続けて」で再開できます。対戦前の実装・模擬検証と、実際のプレイは分けます。

## プレイ担当の Codex の手順

**対戦の指示を受けてから実行します。** 実対局の判断中に完全ログ (`runs/`)、ビューアー用API、seed、乱数状態、相手のNEXTを読みません。盤面評価用の独自スクリプト・探索botに手の選択を委ねず、以下の専用コマンドから得た公開観測と許可された試し読みだけで自分で判断します。実装やテストを読む場合は対戦の判断と区別してください。

```bash
# サーバー上で読み込まれている Codex 対局を確認（系列・盤面は含まない）
npm run agent -- list

# 指定対局の公開盤面、合法手、ルール説明、前回メモを取得
npm run agent -- observe RUN_ID

# 相手の番なら最大50秒だけ待ち、自分の番で観測を返す
npm run agent -- wait RUN_ID --after PREVIOUS_DECISION_ID --timeout-ms 50000
```

実行先は既定で `http://127.0.0.1:3210`。開発用の別ポートだけ使う場合は `STACKINGBENCH_URL=http://127.0.0.1:3211`。専用CLIはローカルHTTP以外を拒否し、リダイレクトを追いません。

観測の `decisionId` は局面ごとに変わります。自分の番以外には盤面・合法手を返さず、`ready:false` の状態だけを返します。終了時は `status` と結果を返します。`wait` が `waiting:true` を返した場合は待機時間の終了であり、失格や手の確定ではありません。相手待機中に定期的な実況を繰り返す必要はありません。

1手ずつ判断します。必要なら以下のJSONを作業用ファイルに保存し、試し読みします。

```json
{"decisionId":"観測のdecisionId","node":"root","moveId":"m0012","requestId":"preview-1"}
```

```bash
npm run agent -- preview RUN_ID --file /tmp/stackingbench-preview.json
```

`node` は `root` または以前に返されたノードID。深さ、未知NEXT、未来のおじゃま穴の境界は既存の試し読みと同じです。`requestId` が同じで内容も同じなら保存済みの結果を返し、予算を再消費しません。別の試し読みでは新しいIDを使います。省略時はCLIがUUIDを生成しますが、通信失敗後に同じ要求を再送する場合はファイル側にIDを指定してください。観測を再取得しても予算はリセットされません。

選択が決まったら、**最新のルート観測**の合法手IDを送ります。深いノードでだけ有効なIDを最終手に使いません。

```json
{"decisionId":"観測のdecisionId","moveId":"m0012","reason":"短い選択理由","memo":"次の判断への短いメモ","agentModel":"GPT-6 Astra","reasoningEffort":"high"}
```

```bash
npm run agent -- choose RUN_ID --file /tmp/stackingbench-choice.json
```

`--file -` で標準入力のJSONも受け付けます。`reason` は最大400文字、`memo` は240文字、`agentModel` は160文字です。モデル名・推論レベルが分かる場合は `agentModel` と `reasoningEffort` に実際の値を指定します。推論レベルは `none` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max` / `ultra` を受け付け、小文字で保存します。不明なら推測せず省略します。省略した項目は対局開始時の記録用設定を使い、明示的なnullは未記録として扱います。途中でモデルや推論レベルを変更した場合は、その後の各判断で実際の値を送ってください。

開始時の値はheaderの `config.players[].agentModel` / `reasoningEffort`、各手の使用値はdecisionの `execution.model` / `execution.reasoningEffort` に保存します。`execution.provenance` で `user-configured`（対局設定）・`agent-reported`（判断時の申告）・`unknown` を区別します。サーバーの自動検証済み情報ではありません。リプレイは表示中の手までの記録を参照し、保存対局一覧は記録されたモデル・推論レベルの組合せを表示します。以前のログの空欄は推測で補いません。

応答の `acceptedDecisionId` が確定した局面、`decisionId` が次のCodex局面（相手の番・終了ならnull）です。まだ自分の番なら最新の `observe` を取り直して次の1手へ進み、7固定したら `wait` で待ちます。通信結果が不明な場合は現在の状態を取得して確定の有無を確認します。古い `decisionId` の再送は拒否し、次のミノを誤って固定しません。

## 記録と比較条件

- ルールv1・ゲームエンジン・SRS経路は変更しません。最終手はサーバーの合法手と保存経路で実行します。
- `agent-event` として観測、試し読み要求・結果、確定要求、拒否エラーを逐次JSONLに保存します。未確定のまま停止しても試し読み記録を保持します。
- 通常の `decision` には盤面・経路・観測プロンプト・最終JSON・メモ・試し読み履歴を保存します。既存リプレイCLIはイベント行を読み飛ばして状態遷移を再現します。
- この会話の全コンテキスト・内部推論・Codexの実トークン数や料金は取得できません。token・費用はnull、StackingBenchからのモデルAPI呼び出しは0として記録します。自己申告の説明を内部推論の証拠とは扱いません。
- 判断時間は最初の観測取得から確定要求までの経過時間です。途中のユーザー対応や待機も含み、API推論時間との同一視はしません。
- 不正・古い入力は拒否イベントとして残し、対局盤面を変更しません。手動接続のため自動失格は設けません。このエラー条件も通常LLM比較と区別します。失敗を探索botの手へ置き換えることはありません。
- 完全なローカル保存ログや同じマシンの管理権限を封じる仕組みではありません。プレイ時の情報源を専用口に制限する運用であり、既存会話の影響もあるため管理されたモデル性能測定と区別します。

## 開発時の確認

`npm test` と `npm run check` に加えて、`scripts/agent-smoke.js` は Playwright で専用CLI・試し読み再送・待機・7固定交代・画面の自動更新・保存リプレイを検証します。モデルを呼ばず、固定の検証用選択を送ります。実対局のログと混ぜないため別サーバーを使います。

```bash
PORT=3211 STACKINGBENCH_RUNS=/tmp/stackingbench-agent-validation npm start
# 別のターミナル。必要なら PLAYWRIGHT_MODULE / CHROME_PATH を指定
APP_URL=http://127.0.0.1:3211 node scripts/agent-smoke.js
```
