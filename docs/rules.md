# StackingBench 初期仕様 v1

これは初期実装の選択であり、事前にすべて合意された仕様ではない。標準競技ルールの完全再現を主張しない。`src/engine.js` の RULES と各対局ログに値を保存する。

## 盤面・進行

幅10、可視20行、上部バッファ4行。座標は左上 (0,0)、右が+x、下が+y。y=0..3 も文字観測で必ず表示。空きは `.`、固定セルは種類文字、せり上がりは `G`。非可視行は人間画面上の区分であり非公開情報ではない。

独立した32bit xorshift のミノ用・おじゃま用ストリームを各人に持つ。7-bag は Fisher–Yates。双方の seed は対局ログに保存するがプレイヤーに渡さない。先手を設定可能。7固定で交代し、HOLD は固定数に含めない。重力・操作時間制限なし。1判断=1固定。上限は両者合計280固定、到達時は引き分け。先後交換比較では seed をプレイヤーに結びつけたまま先手のみ変更する。

出現は全種 4x4/3x3 枠の左上 (3,2)、向き0。I は4x4枠で中心(1.5,1.5)、O は固定4セル、他は3x3枠で中心(1,1)。左右、下、左右90度回転、ハードドロップを使用。180度なし。出現時の衝突で即敗北し HOLD 救済なし。消去後に y<4 にセルが残れば敗北。おじゃま適用で上からセルが押し出された場合も敗北。相手の出現衝突はその人のターン開始で確認する。固定後、自分のターンが継続する場合は次の出現衝突を確認する。

## SRS と合法手

0,R,2,L の4向き。JLSTZ と I の別々の SRS kick 表を順序通り試す。表の y 上向きを実装では反転する。O の回転は状態を変えないため探索辺から除外。根拠: [SRS の定義とキック表を掲載した研究資料、§2・付録](https://erikdemaine.org/papers/TetrisPieces_FUN2024/paper.pdf)。

スポーンから状態グラフを幅優先探索し、合法な左右・下・回転だけで到達できる着地を列挙。ハードドロップは最後に実行して固定する。距離0のドロップは直前の回転を維持し、距離>0のドロップおよび移動は回転履歴を消す。失敗した操作は探索辺にしない。同一4セル・HOLD・スピン分類の手は代表経路に統合し、分類が異なる手は別ID。IDは局面内のみ有効。幾何学順に固定ソートし、評価順位は付けない。回転向きと最後のキック番号(0..4、0は無補正)を添付する。実行時も保存経路を再生して着地を検証する。

## 消去・攻撃

固定直後、消去前に T の中心の斜め4隅中3隅以上が壁または固定セル、かつ最後の操作が回転なら T-spin。向きの前方2隅が両方塞がるか、最後のキックが第5候補なら full、それ以外は mini。miniで3行消去はfull扱い。0行spinの攻撃は0。

|消去行数|0|1|2|3|4|
|---|---:|---:|---:|---:|---:|
|通常|0|0|1|2|4|
|full T-spin|0|2|4|6|—|
|mini T-spin|0|0|1|6|—|

難消去=4行または行消去を伴うspin。難消去が連続すると2回目以降+1 B2B。0行固定はB2B維持、通常1..3行消去で解除。REN初期-1、消去で+1、0行で-1に戻る。REN追加は index 0.. に `[0,0,1,1,2,2,3,3,4,4,5]`、以後5。全消しは他ボーナスに+10。

処理順: 固定 → spin判定 → 消去 → 攻撃計算 → 自分の予告をFIFO相殺 → 残りを相手の予告末尾へ即時配送 → 0行固定なら自分の残り予告を全量せり上げ → 上端判定 → 交代/次出現 → 手数上限判定。ターン境界に追加のせり上げはない。相手ターン中も予告は蓄積する。

キューは配送ごとの行数packet。穴は受取人のおじゃま乱数で実際のせり上げ時に各行独立・一様に0..9から生成。同じ穴も連続し得る。相殺された行について乱数は消費しない。穴は生成前非公開、生成後盤面で公開。これにより試し読みで未来穴を参照しない。

## 観測・試し読み

自他の24行盤面、HOLD、B2B、REN、予告総量、自己currentとNEXT5、残り固定数、直前結果、合法手を渡す。相手のcurrent/NEXT、seed、bag、乱数状態、予告packet構成は非公開。作戦メモは最大240文字、説明は最大400文字。説明は内部推論の証拠ではない。

プレイヤー種別は `llm` / `llm-preview` / `search`。観測設定は別軸の `text` (実装済み)、`image` / `both` (LLMでは未実装なので明示エラー)。探索は表示エンコーディングに依存せず構造データを読むが、LLM と同じ公開情報境界で探索する。

LLM は JSON で `choose` または `preview` を要求するアプリケーションレベルのツール方式。モデル固有の native tool calling には依存しない。preview は root または過去のnodeと局所move IDを指定する。採用時は必ず root の手を指定する。仮置き結果、盤面、次の合法手を返す。予算は判断ごと32状態遷移。試行した未知境界への遷移も1回に数える。実行前に既知のNEXT5だけのコピーへ切り詰め、乱数状態と相手の将来ミノを除去。未知の穴のせり上げ直前に停止し、盤面は返さず `unknown-garbage`。既知ミノを使い切った固定後は盤面を返し `unknown-next` で停止。空HOLDの次ミノが未知なら当該手は列挙しない。ターン末では `turn-end`。相手の応答を仮定した探索はしない。

探索botは既知範囲の決定的なbest-first探索。候補を幾何学順から均等に取り出すので、32回で全候補を評価できない場合もある。固定評価は穴 -8、総高 -0.45、最大高 -0.8、隣接高差 -0.25、予告 -1、当該固定送信 +2、消去 +1、敗北 -100000。未知穴境界の手は -50000。評価/経路は独立にログ保存。同じ32遷移でも計算量・性能の公平性を保証しない。

## 応答・予算・障害

初期値: temperature=0.2、max_tokens=2048/応答、timeout=120秒/応答、1判断の全呼出し生成予算8192、最大LLM往復34。すべて記録・設定可能。token使用量はサーバーのusageを原形保存し、completion_tokensを合算。usageが無い場合は null とし生成予算に予約上限分を計上。思考出力はサーバーが返したmessageにそのまま保存し、選択JSONとしてはcontentのみ解析。隠れた思考量を推定しない。

不正JSON/ID/ツール要求/出力打切りは説明付きで判断全体につき1度だけ修正機会、再発は失格。HTTP、通信、timeoutは対局無効。予算枯渇は失格。エラー時にもAPI要求・応答・経過時間・usageと種別を保存。botへの代替なし。対局中の明示停止は aborted、成績集計から除外。

出力不正の詳細codeは `invalid-json` / `illegal-move` / `invalid-tool` / `output-truncated` / その他形式違反 `invalid-response`。初回修正で成功した場合も `invalidResponses` と要求ごとのvalidationCodeを記録。開発中の初回ログでは詳細code導入前の `invalid-response` 表記があり、finish_reasonとvalidationErrorで識別できる。

接続条件の `responseParsing` はstrictまたはjson-fence-v1。後者は応答全体を囲む単一のMarkdown JSONコード枠だけを除去し、除去をログに記録する。手やJSON内部は変更しない。さくら接続では後者を既定とし、ローカル既定および過去の記録はstrict。これは受信形式の設定で、ゲームルールv1とリプレイの状態遷移には影響しない。

## 保存・評価

対局は逐次 JSONL (header/decision/end)、headerに初期状態と設定、各decisionに状態、選択経路、説明、メモ、時間、遷移数、API transcript。途中終了でも既存行を保持。viewerは保存盤面で巻き戻し、検証CLIは初期状態から操作を再実行して一致を確認する。局面分岐は任意のリプレイ時点の完全状態を引き継ぎ、プレイヤー設定とメモをリセット。3条件で同一局面を比較可能。

固定数、消去、raw火力、相殺、送信、受けた行、消したGセル・Gを含む消去行、時間、遷移、API回数/usage/欠測、失格/無効を保存。掘り効率は消したG行/受けた行 (分母0ならnull)、火力/固定も算出。ローカル費用はnull (無料という推定値は置かない)。複数seedと先後交換CLIあり。小標本では強さを結論しない。
